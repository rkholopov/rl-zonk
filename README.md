# RL для игры Zonk

Обучение агентов Reinforcement Learning в среде Zonk. Реализованы пять алгоритмов:  
- **Monte-Carlo** (обычный и с Weighted Importance Sampling)  
- **Cross-Entropy Method**  
- **Baseline** (Основан на знаниях об окружении, см. Stratagy_by_math_expectation)  
- **Q-Learning** (табличный)  

Проект структурирован так, чтобы легко менять агентов и гиперпараметры без правки кода.

## Установка

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/rkholopov/rl-zonk.git
   cd rl-zonk
   ```

2. Создайте виртуальное окружение (рекомендуется):
   ```bash
   python -m venv venv
   source venv/bin/activate      # Linux/Mac
   venv\Scripts\activate         # Windows
   ```

3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

## Запуск обучения

Из корневой папки проекта выполните:

```bash
python training/training.py --agent QLearning --episodes 50000
```

### Доступные агенты
- `MonteCarlo`
- `MonteCarloWIS`
- `CrossEntropy`
- `Baseline`
- `QLearning`

### Основные аргументы командной строки

| Аргумент | Описание | По умолчанию |
|----------|----------|--------------|
| `--agent` | Имя агента | `Baseline` |
| `--soft` | Параметр мягкой стратегии (`0.1` – для e-мягкой стратегии, `Sampling` – для сэмплирования) | `0.1` |
| `--alpha` | Скорость обучения (для Q-Learning) | `0.3` |
| `--percentile` | Процент элитных траекторий (для Cross-Entropy) | `85.0` |
| `--episodes` | Общее число эпизодов обучения | `100000` |
| `--eval_interval` | Как часто (в эпизодах) проводить оценку | `10000` |
| `--eval_episodes` | Число эпизодов для оценки | `10000` |
| `--seed` | Неотрицательный seed для воспроизводимого запуска | `None` |

Для воспроизводимого запуска с теми же параметрами добавьте `--seed 42`.
Seed задаёт генераторы бросков среды и действий агента. Оценка использует
отдельный генератор бросков. Без `--seed` генераторы инициализируются случайно.

Пример запуска с параметрами:
```bash
python training/training.py --agent CrossEntropy --percentile 90 --episodes 200000 --eval_interval 5000 --seed 42
```

## Запуск с роллаутами

Из корня проекта:

```powershell
python Training/rollouts.py --agent QLearning --episodes 5000 --rollouts 100 --soft 0.3 --alpha 0.01 --log_interval 500 --seed 42
```

Также доступен запуск `python -m Training.rollouts` с теми же параметрами.

| Аргумент | Значение по умолчанию | Назначение |
|----------|----------------------|------------|
| `--agent` | `QLearning` | Один из пяти агентов проекта |
| `--soft` | `0.3` | Исследование: число от 0 до 1 или `Sampling` |
| `--alpha` | `0.01` | Скорость обучения QLearning |
| `--percentile` | `85` | Процентиль для CrossEntropy |
| `--episodes` | Без ограничения | Число реальных эпизодов |
| `--rollouts` | `100` | Число симуляций в состоянии с несколькими ходами |
| `--log_interval` | `500` | Частота вывода и окно средней награды |
| `--seed` | `None` | Seed агента и сред для воспроизводимости |

Без `--episodes` скрипт работает до остановки через Ctrl+C.
`--episodes 0` ничего не обучает; `--rollouts 0` отключает симуляции.
Среда симуляций переиспользуется с сохранением кеша и отдельным генератором
бросков. Выводится средняя награда реальных эпизодов с роллаутами и время
блока в секундах. Последний неполный блок тоже выводится. Это не отдельная
оценка замороженного агента. При одинаковом seed повторяются награды,
но не время выполнения.

---

## Что выводится в консоль

Каждые `eval_interval` эпизодов печатаются две средние награды:
- **На обучении** – средняя награда за последние `eval_interval` эпизодов.
- **На инференсе** – средняя награда при детерминированном выборе действий (без исследования) за `eval_episodes` эпизодов.

Пример вывода:
```
На обучении: 12.34, На инференсе: 15.67
```

## Gymnasium и формат состояния

Среда `Zonk` наследует `gymnasium.Env`. Все наблюдения — кортежи Python:

```python
(phase, score, num_dice, d1, d2, d3, d4, d5, d6)
```

`phase`: 0 — остановиться или бросить, 1 — выбрать кубики, 2 — конец раунда.
`score` — накопленные очки, `num_dice` — количество доступных кубиков.
Значения брошенных кубиков отсортированы, остальные позиции заполнены нулями.
В фазе 0 все позиции кубиков нулевые; в фазе 2 количество кубиков также 0.
Все элементы — обычные `int`, поэтому состояние сразу подходит для ключа Q-таблицы.

```python
from Enviroment.Zonk import Zonk

env = Zonk()
s, info = env.reset(seed=42)
q = {s: [0.0] * len(info["possible_moves"])}
a = env.action_space.sample(mask=info["action_mask"])
s1, reward, terminated, truncated, info = env.step(a)
```

Пространство наблюдений — `spaces.Tuple`. Для очков используется собственное
`ScoreSpace`: неотрицательные целые числа, кратные 50, без верхнего игрового
лимита. Gymnasium поддерживает это пространство; сторонним библиотекам,
которые работают только со стандартными пространствами, понадобится
преобразование наблюдений. Автоматическое преобразование в плоский массив
для ScoreSpace не реализовано. Старые Q-таблицы с ключами другого формата
потребуют преобразования или повторного обучения.

Агенты получают число доступных ходов через `len(info["possible_moves"])`.
Вызов `agent.action(s, pos_moves, optimal=True)` выбирает действие жадно,
без исследования.

Действие — индекс в текущем `info['possible_moves']`, пространство —
`Discrete(64)`. `action_mask` отмечает допустимые индексы. Недоступный индекс
внутри пространства завершает раунд с потерей очков и `invalid_action=True`.
Действие вне пространства вызывает `ValueError`. После завершения нужен reset.

Для роллаута достаточно передать само состояние:

```python
simulation = Zonk()
s, info = simulation.reset(seed=123, options={"state": env.get_state()})
```

Снимок не содержит генератор случайных чисел. Не задавайте одинаковый seed
всем роллаутам, иначе они будут повторять броски. `reset(seed=None)` продолжает
случайную последовательность. `Zonk(seed=42)` задаёт seed первого reset.

Среда, агенты и обучение используют один формат состояния. Ответ `step`
содержит пять значений, а переход для агентов имеет формат `(s, a, r, s1, pos_moves)`.
Встроенного лимита шагов нет, поэтому `truncated` всегда False. Перед
добавлением TimeLimit необходимо отдельно реализовать обучение на усечённых
траекториях. Число очков в терминальном наблюдении — накопленные очки до
завершения; итоговый результат раунда определяется суммой наград.

## Результаты экспериментов

Средние очки за раунд (seed 42):

| Агент | Обычное обучение, 2 млн раундов | Игра со 100 роллаутами |
|---|---:|---:|
| MonteCarlo | 500,4 | 500,0 |
| MonteCarloWIS | **521,3** | **539,5** |
| QLearning | 503,3 | 503,6 |
| CrossEntropy | 308,4 | 416,0 |

**Baseline — необучаемая стратегия сравнения: 498,1 очка** по 300 000 тестовым
раундам. После обычного обучения агенты оценивались на 100 000 отдельных
раундов. Для роллаутов показано среднее за реальные раунды 5 001–10 000:
симуляции и обновления агента продолжались во время измерения.

### Гиперпараметры и условия эксперимента

Параметры относятся именно к результатам в таблице; значения по умолчанию
в CLI могут отличаться.

| Параметр | Обычное обучение | Игра с роллаутами |
|---|---|---|
| Число реальных раундов (`episodes`) | 2 000 000 | 10 000 |
| Исследование (`soft`), все четыре RL-агента | 0.1 | 0.3 |
| Скорость обучения QLearning (`alpha`) | 0.3 | 0.1 |
| Процентиль CrossEntropy (`percentile`) | 85 | 85 |
| Размер пакета CrossEntropy | 10 000 траекторий | 10 000 траекторий, включая симуляции |
| Число симуляций (`rollouts`) | 0 | 100 перед каждым состоянием с несколькими действиями |
| Seed агента и реальной среды | 42 | 42 |
| Seed среды симуляций | Не используется | 43 |

**Выбор действий.** MonteCarlo, MonteCarloWIS и QLearning используют
epsilon-жадную стратегию: с вероятностью `soft` выбирается равновероятное
случайное допустимое действие, иначе — действие с максимальным Q.
CrossEntropy смешивает распределение частот действий с равномерным:
`(1 - soft) * policy / sum(policy) + soft / num_actions`.
Режим `Sampling` в результатах таблицы не использовался.

**Параметры алгоритмов.** Начальные значения Q у MonteCarlo, MonteCarloWIS
и QLearning равны 1500 для каждого действия нового состояния. Награды
не дисконтируются (эквивалент `gamma=1`). MonteCarlo обновляет Q средним
наблюдавшихся возвратов, MonteCarloWIS — взвешенным средним; постоянная
`alpha` используется только QLearning. CrossEntropy каждые 10 000 траекторий
отбирает траектории с суммарной наградой не ниже 85-го процентиля, делит
прежние счётчики политики на 2 и добавляет частоты действий из отобранных
траекторий. Параметр `percentile` используется только CrossEntropy.

**Работа роллаутов.** Каждая симуляция начинается из текущего состояния
реальной игры и продолжается до конца раунда. После каждой симуляции агент
обновляется; реальное действие затем выбирается жадно (`optimal=True`).
Полная реальная траектория также передаётся в обучение после завершения
раунда. Генератор симуляций не перезапускается с одинаковым seed перед каждым
роллаутом. Все агенты в обоих режимах начинали с нуля: таблицы из обычного
обучения в режим роллаутов не переносились.

**Оценка.** После обычного обучения использовались 100 000 отдельных раундов
с `optimal=True`, без обновлений, на копии агента; seed финальной тестовой
среды — 300062. Для роллаутов отдельной проверки без симуляций не было:
усреднялись награды реальных раундов 5 001–10 000 с работающими роллаутами.
Для Baseline использована оценка первой серии: по 100 000 раундов с seed
100042, 100123 и 102026, всего 300 000 раундов.

### Вывод

Лучший результат в этой серии показал **MonteCarloWIS**: +4,7% к Baseline после
обычного обучения и +8,3% с роллаутами. MonteCarlo и QLearning достигли примерно
уровня Baseline, CrossEntropy остался ниже. Это результаты одиночных длинных
запусков с разными вычислительными бюджетами, а не доказательство устойчивого
превосходства или большей вычислительной эффективности.
