# RL для игры Zonk

Обучение агентов Reinforcement Learning в среде Zonk. Реализованы пять алгоритмов:  
- **Monte-Carlo** (обычный и с Weighted Importance Sampling)  
- **Cross-Entropy Method**  
- **Baseline** (Основан на знаниях об окружении, см. Stratagy_by_math_expectation)  
- **Q-Learning** (табличный)  

Проект структурирован так, чтобы легко менять агентов и гиперпараметры без правки кода.

## Установка

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/rkholopov/rl-zonk.git
   cd rl-zonk
   ```

2. Создайте виртуальное окружение (рекомендуется):
   ```bash
   python -m venv venv
   source venv/bin/activate      # Linux/Mac
   venv\Scripts\activate         # Windows
   ```

3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

## Запуск обучения

Из корневой папки проекта выполните:

```bash
python training/training.py --agent QLearning --episodes 50000
```

### Доступные агенты
- `MonteCarlo`
- `MonteCarloWIS`
- `CrossEntropy`
- `Baseline`
- `QLearning`

### Основные аргументы командной строки

| Аргумент | Описание | По умолчанию |
|----------|----------|--------------|
| `--agent` | Имя агента | `Baseline` |
| `--soft` | Параметр мягкой стратегии (`0.1` – для e-мягкой стратегии, `Sampling` – для сэмплирования) | `0.1` |
| `--alpha` | Скорость обучения (для Q-Learning) | `0.3` |
| `--percentile` | Процент элитных траекторий (для Cross-Entropy) | `85.0` |
| `--episodes` | Общее число эпизодов обучения | `100000` |
| `--eval_interval` | Как часто (в эпизодах) проводить оценку | `10000` |
| `--eval_episodes` | Число эпизодов для оценки | `10000` |
| `--seed` | Неотрицательный seed для воспроизводимого запуска | `None` |

Для воспроизводимого запуска с теми же параметрами добавьте `--seed 42`.
Seed задаёт генераторы бросков среды и действий агента. Оценка использует
отдельный генератор бросков. Без `--seed` генераторы инициализируются случайно.

Пример запуска с параметрами:
```bash
python training/training.py --agent CrossEntropy --percentile 90 --episodes 200000 --eval_interval 5000 --seed 42
```

---

## Что выводится в консоль

Каждые `eval_interval` эпизодов печатаются две средние награды:
- **На обучении** – средняя награда за последние `eval_interval` эпизодов.
- **На инференсе** – средняя награда при детерминированном выборе действий (без исследования) за `eval_episodes` эпизодов.

Пример вывода:
```
На обучении: 12.34, На инференсе: 15.67
```

## Gymnasium и формат состояния

Среда `Zonk` наследует `gymnasium.Env`. Все наблюдения — кортежи Python:

```python
(phase, score, num_dice, d1, d2, d3, d4, d5, d6)
```

`phase`: 0 — остановиться или бросить, 1 — выбрать кубики, 2 — конец раунда.
`score` — накопленные очки, `num_dice` — количество доступных кубиков.
Значения брошенных кубиков отсортированы, остальные позиции заполнены нулями.
В фазе 0 все позиции кубиков нулевые; в фазе 2 количество кубиков также 0.
Все элементы — обычные `int`, поэтому состояние сразу подходит для ключа Q-таблицы.

```python
from Enviroment.Zonk import Zonk

env = Zonk()
s, info = env.reset(seed=42)
q = {s: [0.0] * len(info["possible_moves"])}
a = env.action_space.sample(mask=info["action_mask"])
s1, reward, terminated, truncated, info = env.step(a)
```

Пространство наблюдений — `spaces.Tuple`. Для очков используется собственное
`ScoreSpace`: неотрицательные целые числа, кратные 50, без верхнего игрового
лимита. Gymnasium поддерживает это пространство; сторонним библиотекам,
которые работают только со стандартными пространствами, понадобится
преобразование наблюдений. Автоматическое преобразование в плоский массив
для ScoreSpace не реализовано. Старые Q-таблицы с ключами другого формата
потребуют преобразования или повторного обучения.

Агенты получают число доступных ходов через `len(info["possible_moves"])`.
Вызов `agent.action(s, pos_moves, optimal=True)` выбирает действие жадно,
без исследования.

Действие — индекс в текущем `info['possible_moves']`, пространство —
`Discrete(64)`. `action_mask` отмечает допустимые индексы. Недоступный индекс
внутри пространства завершает раунд с потерей очков и `invalid_action=True`.
Действие вне пространства вызывает `ValueError`. После завершения нужен reset.

Для роллаута достаточно передать само состояние:

```python
simulation = Zonk()
s, info = simulation.reset(seed=123, options={"state": env.get_state()})
```

Снимок не содержит генератор случайных чисел. Не задавайте одинаковый seed
всем роллаутам, иначе они будут повторять броски. `reset(seed=None)` продолжает
случайную последовательность. `Zonk(seed=42)` задаёт seed первого reset.

Среда, агенты и обучение используют один формат состояния. Ответ `step`
содержит пять значений, а переход для агентов имеет формат `(s, a, r, s1, pos_moves)`.
Встроенного лимита шагов нет, поэтому `truncated` всегда False. Перед
добавлением TimeLimit необходимо отдельно реализовать обучение на усечённых
траекториях. Число очков в терминальном наблюдении — накопленные очки до
завершения; итоговый результат раунда определяется суммой наград.
